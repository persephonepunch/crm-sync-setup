1 · Staff: what changes when the VPN goes

How the migration runs

Objections to replacing the VPN

"Our VPN works."
It also gives every connected user the whole network, and VPN appliances are among the most attacked devices on the internet. With per-app access, a stolen password opens one app.
"Our legacy apps won't work."
Anything that speaks TCP or UDP runs over the client and the tunnel, and web apps need no client at all. Pilot the hardest app first.
"It will be slower."
Users connect to the nearest Cloudflare data centre instead of hairpinning through one head office, which matters most for teams spread across a region like APAC.
"What do we show the auditor?"
Every allow and deny is logged per user and per app, which is the evidence SOC 2 access controls (CC6) ask for.

4 · Permissions and rendering: why Auth Me changes SSR

On a Node server, personalising a page usually means rendering it per request (SSR), so nothing can be cached for everyone. With Xano Auth Me returning each caller's roles and capabilities, the page can stay one cached copy (ISR) at the edge, and only the permission answer is per caller. The same answer serves a browser, a Web Component in any framework, and an AI agent through /mcp.

The runtimes line up too. Custom code steps in Xano (Lambdas) run JavaScript or TypeScript on Deno, which uses the same web-standard Request and Response model as Cloudflare Workers. A typical AWS setup runs Node, with its own request objects and packaging. Code written against web standards moves between Xano and the edge with little change; code written for Node usually needs porting.

Node server, SSR per userEdge ISR + Xano Auth Me
Where permissions liveBaked into each rendered pageOne Auth Me answer per caller: roles and capabilities
CachingPersonalised pages cannot be sharedThe page is cached once and served to everyone

Where the check is enforcedIn the render, per frameworkIn the Worker, on every action, for every caller

5 · Isolates, containers, VMs: separation as a control

Each layer runs code with less reach than the one below it, and nothing moves down a layer unless the job needs more control. Separation is the security benefit: a fault or a compromise stays inside the layer where it happened.

On-demand connectors to SAP, Azure and AWS, after human review

A connector to an enterprise system runs as a container that does not exist until a person has approved exactly what it may read and write. It starts with short-lived credentials scoped to that approval, reaches Xano only through the API, and stops when the job is done.

Human stakeholders: the least-privilege ladder to on-premises systems

Each person holds only the rung their job needs. The same request needs three different people: one asks, the data owner approves, security issues the credentials. No one can do all three, so no single account, stolen or misused, can open an on-premises system on its own.

Secrets along the escalation

The ladder decides who may act; these rules decide where a secret may exist while they do. A secret only ever lives in a secret store, reaches a process at the moment it starts, and expires with the job. Plain-text files on a laptop are the weakest link, so they hold configuration and nothing else.

Where a secret could sitRule
.env and other text filesConfiguration only: URLs, project and region names, IDs. Never a key or token. Owner-only permissions (600), never committed.
.venv (Python packages)Dependencies only. Never holds a secret, never committed, and rebuilt from the lock file rather than copied.
Developer sign-in filesCloud sign-in tokens on a laptop are real credentials: owner-only, short sessions, and revoked when the person leaves the ladder.
Container imagesNo secret is ever baked into an image. The connector's credentials are injected when it starts, from the secret store, and expire when it stops.
Cloudflare WorkersEncrypted secrets, typed straight into the platform at a prompt. Never pasted into chat, email or a ticket.
XanoEnvironment variables in the workspace; functions read them, people do not copy them out.
The key register and the ledgerRecord each key by fingerprint (the first characters of its hash), who rotated it and when. Never the value.
Each rung of the ladderOnly Security (rung 6) handles secret values, and only to put them into a store. Every other rung sees a fingerprint, a status or nothing.

6 · Supply chain: the lock file, and who may publish

What runs in production should be exactly what was reviewed. The lock file fixes which code goes in; the publishing rule fixes who can put it live. An outside team can write, test and stage everything, but it never holds a credential that publishes to production.

The lock file

Build once in the US, run in Korea: the Xano image flow

Xano does not build containers; it runs a finished image pulled from a registry. The Dockerfile and lock file live in your repository, the image is built once in your reviewed pipeline, and each Xano instance pulls that exact image by digest. The image holds code only, so it can be built and stored in the US while Korean personal data never leaves the Seoul instance.

Interactive publishing: no external team holds live credentials

External developers work in their own development account or the staging environment, with a token that can reach staging and nothing else. Production is published by the owner's own person, signed in to Wrangler interactively in a browser, from the reviewed commit. The sign-in belongs to a named person, can be revoked with their account, and is never handed over as a token.

7 · Shape: designed in the US, shipped as code, no design-tool dependency at run time

A shape is the data model a design surface authors and the runtime renders: fields, where each value came from, and a version. It is designed once (model, view and controller agreed), then compiled into a versioned file that ships in the release like the lock file. From then on the data design is code: day-to-day compute and transport read the compiled shape, and nothing at run time calls Webflow or reaches back to the US.

A VPN trusts the network, and middleware trusts the record. Under the Cloudflare umbrella nothing is trusted by default: the person, the device, the agent and the sync are each checked on every request, against one system of record.
